Sigma Bridge HOWTO

Short version, five steps.

1. FILL data.txt
   One line is one refresh token for one Sigma account. The bot exchanges it for an access
   token on every call and writes the rotated refresh token back to the same line, so you
   only paste it once. One line is one account; the cycle takes them in order.

2. POINT AT A PROXY (OPTIONAL)
   Open proxy.txt and put one proxy per line, for example:
       http://user:pass@host:port
   Leave it empty for a direct connection. One line is one exit address.

3. CHECK config.json
       sleep_seconds   pause between requests
       round_robin     true rotates across accounts, false always uses the top line
       sticky          how many requests an account serves before the next one is used
       port            the HTTP port the bridge listens on

4. BUILD
       cargo build --release
   or let the wrapper do it:
       ./run.sh build

5. RUN
       ./run.sh              foreground, serves on the configured port
       ./run.sh bg           background, log in sigmabridge-bot.log
       ./run.sh screen       detached screen session
       ./run.sh stop         stop the background run
   Point any OpenAI client at http://<host>:<port>/v1 with model sigma-flash.

Windows
   The .exe comes from the GitHub Actions release, not from a local build. Put the exe in a
   folder with data.txt and config.json, then run:
       sigmabridge-bot.exe serve
   The access token refresh is automatic; nothing else to change.

Quick checks without data.txt
   SIGMA_ACCESS=<access_token> ./target/release/sigmabridge-bot probe
   SIGMA_ACCESS=<access_token> ./target/release/sigmabridge-bot tokenchat --text "hi"

data.txt is an input; the bot rewrites the line it owns and never touches the others.
